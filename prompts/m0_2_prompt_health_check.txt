Работаем над учебным бэкендом магазина кроссовок. Python 3.11+, FastAPI, синхронный SQLAlchemy 2.0, PostgreSQL 17, Alembic. API работает на компьютере, PostgreSQL — в Docker. Прочитай приложенные актуальные файлы и используй их имена. Не выполняй следующие модули. Реальные секреты в приложенном контексте заменены на <REDACTED>.

Вход: работающий PostgreSQL из Compose; requirements.txt содержит зафиксированные FastAPI, Uvicorn, SQLAlchemy, psycopg и python-dotenv. Приложены папка проекта, compose.yaml, обезличенный .env.example

Создай app/core/config.py, app/database.py, app/main.py. Загружай .env относительно корня проекта через python-dotenv, не заменяя уже заданные переменные окружения. DATABASE_URL обязателен. Создай один Engine на процесс и фабрику sync Session. Для локального опыта задай connect_timeout=3, pool_timeout=3 и PostgreSQL statement_timeout=3000, pool_pre_ping=True. Объясни, что три таймаута ограничивают разные ожидания и не равны единому дедлайну HTTP.
GET /health должен выполнять SELECT 1 через with engine.connect(). Успех: 200 и {"status":"ok"}; ожидаемая ошибка доступности или ожидания пула: 503 и {"status":"unavailable"}. Не возвращай клиенту пароль, URL подключения или traceback. Не маскируй все ошибки программы широким except Exception. При завершении приложения освободи Engine. Не вызывай create_all, не создавай таблицы и не добавляй бизнес-маршруты.
Запуск: python -m uvicorn app.main:app --reload --port 8000. Приёмка в другом терминале: /docs и /openapi.json доступны, GET /health =200; остановить только учебный сервис db → /health=503; поднять db и дождаться healthy → тот же процесс API снова выдаёт 200. Зафиксируй все три тела ответа. Открытие /docs само по себе не подтверждает БД.
